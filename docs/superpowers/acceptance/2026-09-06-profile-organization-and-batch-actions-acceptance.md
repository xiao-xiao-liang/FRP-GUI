# Profile 组织与批量编排验收清单

## 自动化验证

Gemini 完成实现后必须执行并记录实际结果：`pnpm test`、`pnpm build`、`cargo test --manifest-path src-tauri/Cargo.toml`、`git diff --check` 与 `git status --short`。

验收通过条件：前端测试、前端构建和 Rust 测试均为零失败；`git diff --check` 无错误。既有未提交改动必须保留，不能用重置、清理工作区或删除测试掩盖问题。

## 数据迁移与安全

- 使用一个没有 `groupId`、`tags`、`isPinned` 的旧 Profile 启动，列表正常显示为未分组、无标签、未置顶。
- 旧版设置缺少 `profileSort` 时，设置页默认显示“置顶且最近更新”，且其余设置值保持不变。
- 将 `profileSort` 单独写成非法值后，只有该字段回退默认值，其他有效设置保持不变。
- 新建、重命名和删除分组后，刷新应用，分组与 Profile 关联保持正确。
- 删除一个分组后，属于该分组的 Profile 仍存在，但均显示为未分组。
- 检查 `frp_gui_profiles` 与 `frp_gui_profile_groups`：其中不得出现 `rawToml`、Token、服务器密码、私钥或其他凭据内容。
- 在系统凭据库不可用的既有错误场景下，组织操作不得覆盖或伪造凭据保存成功状态。

## 分组、标签与排序

- 分组名称去除首尾空白；空名称、超过 30 个字符和不区分大小写重名均被拒绝，并显示明确原因。
- 标签去除首尾空白；同一 Profile 中忽略大小写重复的标签只保留一个；第 11 个标签和超过 24 个字符的标签被拒绝。
- 卡片和表格视图均显示置顶标记、分组名和最多两个标签；超过两个标签时显示剩余数量。
- 未分组或无标签的 Profile 不显示空标签占位。
- 切换三种排序后顺序正确；相同主排序值的 Profile 顺序稳定且可重复。
- 克隆一个带分组、标签和置顶状态的 Profile：新项保留分组和标签，但未置顶。

## 组合筛选与选择

- 分组、标签、状态、类型和关键词同时设置时，结果必须同时满足所有条件。
- 改变任一筛选条件、排序或 Profile 数据集后，列表回到第一页。
- 在多页筛选结果中使用“选择全部”，选择数量等于全部筛选结果，不只等于当前页。
- 更改筛选条件后，已不在筛选结果中的选择自动清除；删除 Profile 后其选择也自动清除。
- 卡片和表格切换后，当前筛选、排序和有效选择保持一致。

## 批量操作

- 选择 `stopped`、`error`、`running` 和 `starting` 混合项执行批量启动：仅前两类依当前排序串行启动，界面说明跳过数量。
- 批量停止前出现确认；确认后仅 `running` 项依当前排序串行停止，其余状态被跳过并说明数量。
- 批量移动分组可选任意现有分组或“未分组”，只改变 `groupId`，不改变状态、TOML 或凭据。
- 已选择任意 `starting`、`running` 或 `stopping` 项时，批量删除不可用，且工具提示说明必须先停止连接。
- 所选项目均为 `stopped` 或 `error` 时，批量删除需要确认；成功后 Profile 消失，关联的系统凭据也通过既有删除路径被清理。
- 批量操作执行期间，重复点击批量按钮不会产生第二次请求。
- 失败项保留在列表中，并显示既有错误反馈；成功删除的项目从选择中移除。

## 回归与环境检查

- 在卡片与表格视图完成创建、编辑、单项启动、单项停止、删除和克隆，既有功能行为不回退。
- 在浏览器预览环境触发启动、停止和删除，继续显示既有 Tauri 环境限制提示，不得假装执行成功。
- 在真实 Tauri 应用中执行至少一次批量启动、停止和删除，确认托盘、窗口关闭和退出应用的既有行为不受影响。
- 检查窄窗口与键盘操作：筛选控件、复选框、批量工具条和确认对话框均可访问，焦点不会丢失。
