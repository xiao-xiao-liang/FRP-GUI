# P1-C3.1「可信 FRPC 桌面运行闭环与 Windows 打包准备」Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` task-by-task. Before Task 1, read the repository `AGENTS.md`, then use `superpowers:test-driven-development` for every behavior change, `superpowers:systematic-debugging` for any unexpected test/build failure, and `superpowers:verification-before-completion` before reporting a Task as complete. This workspace is not a Git repository: do not run `git commit`, `git add`, `git reset`, or create a worktree. Do not connect to any remote server, request credentials, or run real FRPC against a cloud host in any Task.

**Goal:** Make the Tauri desktop window the only runtime environment that can start, stop and observe local FRPC; show only process-supervised state and real local stdout/stderr logs, while making the ordinary browser preview a non-executable UI preview. Make the Windows desktop build reproducible.

**Architecture:** A Rust `frpc_runtime` module owns one local child process per profile ID, performs a bounded early-exit check, forwards sanitized stdout/stderr as Tauri events, and emits terminal state changes when the process exits. The React app consumes those events through a single IPC subscription and no longer derives `running` from a browser simulation or a successful `spawn()`. Vite in a normal browser is intentionally read-only; the same Vite page inside Tauri gets native IPC. Windows packaging is restored by adding the Tauri CLI and generated icon assets.

**Tech Stack:** React 19, TypeScript, Vitest, React Testing Library, Tauri v2, Tokio, Rust, `sysinfo`, `@tauri-apps/api`, `@tauri-apps/cli`.

**Hard safety and truthfulness rules:**

1. Delete—not hide—every browser-generated PID, random successful login, random heartbeat, proxy-added message, browser process timer and fake status transition.
2. In a normal browser, every runtime API (`startProfileInstance`, `stopProfileInstance`, runtime-log subscription and TCP diagnosis) must fail with a desktop-only message and must not mutate a profile to `running`.
3. Rust may start only a local `frpc` core selected from the existing core manager. The frontend does not send a command, arguments, environment variables, PID, arbitrary config path or process-control instruction. Validate the supplied core path as an existing local file, invoke only fixed `--version` and fixed `-c <managed-config>` arguments, and reject output that does not identify `frpc`.
4. A `spawn()` result is not `running`. Only a child that survives the confirmation window gets a `running` event. Early exit, unexpected later exit and stop failure must never produce a successful-running state.
5. Do not expose Token, private keys, passwords, full TOML, full command lines, environment values or raw OS errors in Tauri state/log events, React state, localStorage, Toasts, snapshots or documentation.

- [ ] **Step 3: Add `frpc_runtime.rs` with a bounded, owned child lifecycle**

Implement a dedicated module; do not keep adding asynchronous lifecycle code to `lib.rs`.

```rust
pub const RUNTIME_LOG_EVENT: &str = "frp-runtime-log";
pub const RUNTIME_STATE_EVENT: &str = "frp-runtime-state";
const CONFIRM_WINDOW: Duration = Duration::from_millis(800);

#[derive(Serialize, Clone, PartialEq, Eq)]
#[serde(rename_all = "snake_case")]
pub enum RuntimeStatus { Starting, Running, Stopping, Stopped, Error }

#[derive(Serialize, Clone)]
#[serde(rename_all = "camelCase")]
pub struct RuntimeStateEvent {
    pub profile_id: String,
    pub status: RuntimeStatus,
    pub pid: Option<u32>,
    pub timestamp: u64,
    pub error_message: Option<String>,
}

#[derive(Serialize, Clone)]
#[serde(rename_all = "camelCase")]
pub struct RuntimeLogEvent {
    pub profile_id: String,
    pub timestamp: String,
    pub level: String,
    pub message: String,
}

#[derive(Serialize)]
#[serde(rename_all = "camelCase")]
pub struct ProcessCommandResult { pub accepted: bool, pub pid: Option<u32>, pub error: Option<String> }
```

Implement these exact behaviors:

1. Validate `profile_id` with `^[A-Za-z0-9_-]{1,128}$`; derive the TOML filename only from that validated ID and write it under Tauri `app_local_data_dir()/runtime-config/`. Create the directory with restrictive default permissions; never use `std::env::temp_dir()` or a frontend-configured path.
2. Validate `core_path` as an existing canonical local file. Invoke only `core_path --version` with a five-second timeout, capture it privately, require a case-insensitive `frpc` marker, and return a fixed safe error when invalid. Never return captured version-check output.
3. Spawn only `core_path -c managed_config_path`, pipe stdout/stderr, emit `starting`, then wait up to `CONFIRM_WINDOW` for `child.wait()`. Early nonzero/zero exit emits `error` with the generic safe message `FRPC 在启动确认阶段退出，请查看桌面端真实日志` and returns `accepted: false`.
4. If the process survives, register its PID/state before launching the long-lived `child.wait()` task, emit `running`, return `accepted: true`, and forward each stdout/stderr line through `sanitize_runtime_log`. The forwarding task must preserve profile ID and classify stderr as `error`.
5. The wait task removes the matching registry entry and emits `stopped` only after an explicit stop request; otherwise emits `error` with `FRPC 进程已意外退出`.
6. `stop_profile` emits `stopping`, uses only fixed platform APIs/arguments to terminate the registered PID, checks the returned exit status, waits with a finite poll for the monitor to observe exit, and emits/returns failure if it cannot confirm termination. A missing profile is rejected as `accepted: false`, never treated as success.
7. Add `shutdown_all()` for Tauri app exit; it requests termination for all supervised PIDs and clears the registry. It must not touch non-supervised system processes.
8. `sanitize_runtime_log` must replace values following `token`, `password`, `secret_key`, `authorization`, and PEM-boundary content with `******`; bound each emitted message to 4 KiB and never include `raw` separately.

## Plan self-review

- **Spec coverage:** Task 1 removes browser false success and blocks preview actions; Task 2 supplies process supervision, safe config storage, early-exit detection, log sanitation and truthful stop semantics; Task 3 makes UI state/log presentation backend-event authoritative; Task 4 provides Tauri development/packaging readiness and documents test boundaries.
- **Truthfulness:** No branch invents a PID, successful FRPC login, proxy registration or live log. A process only becomes running after a bounded survival check and a Rust state event.
- **Security:** Browser has no runtime fallback, frontend does not pass arbitrary process controls, managed configuration paths are derived from validated IDs, logs are sanitized and bounded, and no cloud access is authorized.
- **Compatibility:** Existing P1-C3 server-node and FRPS deployment code remain unchanged. Existing Tauri commands retain their names while returning a more accurate `accepted` result. The plan deliberately avoids unrelated dependency upgrades and Git operations.
