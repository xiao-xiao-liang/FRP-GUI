# FRP 核心下载兼容与完整性修复设计

## 目标

恢复默认国内镜像下载，同时保留官方 Release 的资产身份验证和 SHA-256 完整性校验，并为归档下载施加内存上限。

## 根因

核心管理页将官方资产 URL 重写为 `ghproxy.net` 或 `download.fastgit.org`。Rust 命令随后只接受 `github.com/fatedier/frp` 前缀，导致默认的 `ghproxy` 设置必然被拒绝。

## 设计

前端不再把改写后的 URL 作为可信输入传给 Rust，而是传递官方 Release URL 和镜像标识（`official`、`ghproxy`、`fastgit`）。Rust 先从官方 URL 提取 release tag 与资产名、构造官方下载校验和地址，并只允许这三个镜像标识。随后由 Rust 构造实际传输 URL；无论使用何种镜像，下载字节都必须匹配从官方 Release 获取的 SHA-256。

归档响应按块读取并同步更新 SHA-256；累积大小超过 100 MiB 时立即返回失败，不解压任何内容。归档校验通过后才进入现有解压流程。

## 兼容性与错误处理

保留当前 UI 中的镜像选择、默认值和文案。来自旧前端的任意非官方 `downloadUrl` 仍会被拒绝。未知镜像标识、无校验和资产、超过大小限制和哈希不一致均返回非成功结果，不写入解压文件。

浏览器/Vite 预览不执行真实核心下载或解压；该能力仅在 Tauri 桌面端可用。同步移除开发服务器的下载中间件，避免本机预览路径成为绕过桌面下载校验边界的入口。

## 验证

先添加 Rust 单测验证镜像 URL 只能由官方身份与受控镜像生成、大小限制拒绝超限数据；添加前端 IPC 合约测试，确认桌面端将原始官方 URL 与镜像标识分别传入，并验证浏览器预览不会发起下载请求。测试先失败，再实施最小改动，最后执行前端和 Rust 全量测试及 `git diff --check`。
