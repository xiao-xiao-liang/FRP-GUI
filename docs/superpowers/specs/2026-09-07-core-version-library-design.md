# FRP 核心版本库、目录导入与可恢复下载设计

## 目标

将现有“本地核心列表 + 在线 Release 列表”的分离呈现，调整为以 GitHub 官方 Release 为唯一目录的版本库：每一个 Release 只有一张版本卡片（或一行表格记录），本地已经验证且匹配当前电脑平台/架构的 FRPC 会使对应版本显示无圆点的绿色“已下载”胶囊。

用户可以选择一个曾经解压过 FRP 的目录。目录中只有一个版本时直接导入；其中包含多个版本子目录时，应用扫描全部可识别的 FRPC 并批量登记。未安装的当前平台匹配资产可从卡片进入下载，选择镜像与安装目录后完成下载、哈希校验、解压及 FRPC 验真。下载中断后支持在条件满足时断点续下。

## 已确认的产品决策

1. GitHub 官方 Releases 是唯一的版本列表、发布时间、下载量和官方校验元数据来源；镜像不作为可切换的版本列表来源。
2. 镜像仅影响实际资产下载 URL。镜像不可用时必须提示用户切换镜像或使用 GitHub 官方源，不能静默切换。
3. “已下载”严格按**当前电脑的 OS + CPU 架构**判断。存在其他平台或架构的同版本文件不能让当前版本卡显示“已下载”。
4. 用户选择的目录支持单个 FRPC 与多个版本子目录的批量扫描；每个候选都必须以可执行文件的只读版本检查为准，不能仅根据目录名或文件名推断版本。
5. 下载、校验、解压和最终 FRPC 验真复用同一根进度条；只有解压和验真都成功，任务才是完成并显示“已下载”。
6. 下载速度每秒刷新。预计剩余下载时间在至少获得三个连续非零速度样本后显示，使用指数移动平均速度计算；速度变化不停止 ETA 更新。

## 范围与边界

### 包含

- 在 `CoreManagerPage` 的既有卡片/表格视图中，以官方 Release 为主数据源呈现版本。
- 选择本地 FRP 目录、递归扫描候选 FRPC、批量验真与批量登记。
- 现有下载弹窗增加镜像、目标目录、匹配资产、统一进度、取消、继续与清理未完成任务的交互。
- Rust 端受控下载、官方 SHA-256 校验、临时解压、FRPC 版本检查、原子提交安装和断点续下。
- 前端、IPC 与 Rust 的单元/契约测试，以及桌面端人工验收场景。

### 不包含

- 将第三方镜像作为 Release 元数据源，或因镜像生成重复的版本卡片。
- 以目录名、压缩包名等非可执行文件证据登记版本。
- 将未校验的归档、半成品解压目录、FRPS 或其他可执行文件标记为可用 FRPC。
- 静默下载、静默切换镜像、覆盖用户已有安装目录或删除用户导入的文件。

## 数据模型与状态派生

### 版本目录

前端继续通过 `fetchGitHubReleases` 获取 GitHub 官方 Release 列表，并补齐每个 Release 的资产清单、发布时间、总下载量与官方校验信息。每个 `tag` 只生成一个逻辑版本记录，既有卡片/表格视图均从这个版本目录派生，不能分别渲染“本地 v0.71.0”和“在线 v0.71.0”。

### 本地安装项

每个被导入或安装成功的 FRPC 都保留为一条安装项。现有 `FrpCore` 的 `version`、`os`、`arch`、`path`、`isDefault` 与 `status` 是基础字段；必要时新增来源资产名、登记时间等非敏感元数据。不同路径或不同平台/架构的同版本文件可并存；同一路径重复扫描时去重，不重复登记。

本地路径本身不等于“已下载”。只有路径对应的二进制通过 `inspect_frpc_core`（或等效 Rust 检查）、其版本与卡片 tag 相同、且其 OS/架构与当前电脑匹配时，卡片状态才为“已下载”。当前版本识别以受控执行 `frpc --version` 为准，因此无法在当前电脑运行的异构二进制不能被猜测性登记；卡片保持“可下载”，并明确提示当前设备需要下载的 OS/架构资产。

### 卡片状态

| 状态 | 条件 | 卡片呈现与动作 |
| --- | --- | --- |
| 已下载 | 存在匹配当前 OS/架构且验真的本地安装项 | 无圆点绿色 `FeishuPill`；可设默认、更改路径、删除登记 |
| 可下载 | 不存在匹配安装项且没有进行中的任务 | 灰色胶囊；可复制当前镜像链接、选择安装目录后下载 |
| 下载中 | 下载任务处于下载、校验、解压或验真阶段 | 蓝色胶囊、统一进度条、阶段详情、取消 |
| 可继续 | 上次下载中断，缓存与服务端验证仍满足续传条件 | 橙色胶囊；可继续或清除任务 |
| 失败 | 下载、校验、解压或验真失败 | 红色提示和具体原因；可重试或清理任务 |

卡片继续使用项目已有的 `Card`、`FeishuPill`、`Button`、`FeishuDialog`、`FeishuToast`、`FEISHU_FONT_FAMILY` 和既有飞书色板。不得复刻外部截图的紫色侧边条、按钮形态或字体。

### 表格视图状态列

既有表格视图新增独立的“状态”列，不能仅通过操作列或版本名称暗示状态。该列使用与卡片完全一致的 `FeishuPill` 语义和无圆点样式：绿色“已下载”、灰色“可下载”、蓝色“下载中”、橙色“可继续”、红色“失败”。

“下载中”单元格在胶囊下方以紧凑次级文本展示当前阶段和总进度，例如“下载 62%”或“正在解压 4 / 7”；展开下载详情或切换至卡片视图时，仍复用同一个任务状态和进度数据，不产生第二套进度。表格状态列保持可读的最小宽度，其他元数据列按现有自适应规则收缩，右侧操作列继续吸附。

## 本地目录导入

### 流程

1. 用户点击“选择本地已有 FRP 文件夹”，使用现有原生目录选择能力获取目录。
2. Rust 在用户选定目录内递归枚举候选，仅接受文件名为 `frpc` 或 `frpc.exe` 的可执行文件。遍历应设置候选数量上限和错误汇总；遇到异常大目录时提示用户选择更精确的 FRP 根目录，而不是扫描磁盘根目录。
3. 对每个候选执行只读 FRPC 检查，取得版本、程序类型、OS/架构等可验证信息。`frps`、非执行文件、执行失败项和未知版本项不登记。
4. 将结果返回为“已识别、已跳过、失败原因”的批量摘要。前端按真实路径去重，批量加入安装项，刷新版本目录的派生状态。
5. 使用 Toast 与可展开的结果摘要显示识别数量、跳过数量和原因；导入成功的版本卡即时切换为“已下载”。

不因单个候选检查失败中断其他候选；但目录无法读取或遍历超过安全限制时整个任务必须明确失败，不得伪造部分成功。

## 下载、恢复与安装

### 资产和镜像

下载入口预选 `detectHostSystemPlatform` 返回的 OS/架构，并使用 `matchReleaseAsset` 选择相应官方资产。下载弹窗保留当前的 GitHub 官方、ghproxy、FastGit 等镜像选项；该选择只生成资产下载 URL，不能改写版本目录数据和官方 SHA-256 来源。

校验文件始终从 GitHub 官方 Release 元数据关联的校验清单取得并验证；镜像只是不可信的字节传输通道。镜像响应不支持续传、ETag 不一致、内容长度变化或返回内容与预期不符时，必须中止续传并要求用户重新下载或切换镜像。

### 可恢复任务

每个下载任务在应用数据目录的受控缓存中保存：

- 未完成归档 `.part`；
- 任务元数据（Release tag、资产名、镜像 URL、预期大小、已接收字节、ETag/Last-Modified、SHA-256 目标值、目标目录、平台/架构）；
- 任务状态和失败原因。

归档及元数据不写入用户选择的安装目录。应用启动或核心管理页加载时读取未完成任务：当元数据、缓存大小与远端 ETag/Range 响应仍可验证时显示“可继续”；否则显示不可恢复原因并只允许重新下载或清理缓存。成功提交、用户显式清理或不可恢复且用户确认清理后删除缓存。

HTTP Range 请求从现有 `.part` 长度继续。若服务端忽略 Range、返回 200 而非有效部分内容、或实体标识不一致，丢弃本次追加响应，不污染已有安装目录，并给出“该镜像不支持安全续传”的可操作提示。

### 安全安装

1. 下载完成后校验归档 SHA-256；失败则不解压、不登记。
2. 在受控临时目录解压，严格防止压缩包路径穿越，并限制可接受的文件数量/大小。
3. 找到解压后的 `frpc/frpc.exe` 并执行只读版本检查，确认它是客户端、版本和目标平台/架构符合预期。
4. 全部成功后，将临时目录原子提交至用户选择的目标安装目录；不得覆盖目录中已有非本任务文件。若目标已存在且冲突，提示用户选择其他目录或显式处理。
5. 提交完成后新增安装项并刷新卡片状态。取消、哈希失败、解压失败或验真失败只能清理任务临时目录，不能删除用户原有目录。

## 统一进度条

同一版本卡和下载弹窗只出现一根任务进度条。其总完成度按阶段加权单调递增：

| 阶段 | 总进度区间 | 展示内容 |
| --- | --- | --- |
| 下载 | 0–85% | `已下载 / 总大小`、每秒实时下载速度、百分比、当前镜像、目标目录、预计剩余下载时间、取消 |
| SHA-256 校验 | 85–90% | `正在校验 SHA-256`、已耗时和活动状态；不伪造不可精确计算的百分比 |
| 解压 | 90–99% | `已解压文件数 / 总文件数`、阶段百分比、当前文件名（只显示文件名）、目标目录、取消 |
| FRPC 验真与提交 | 99–100% | `正在检查 FRPC 版本并完成安装`；成功后切换为“已下载” |

下载阶段每秒按新接收字节数计算并显示瞬时速度。ETA 的计算规则：

1. 至少已有三个连续非零的秒级速度样本才显示；此前显示“正在计算预计时间”。
2. 用指数移动平均速度计算剩余下载时间，推荐 `EMA = 0.25 × 当前速度 + 0.75 × 上次 EMA`。
3. 每秒随新的样本刷新 ETA；ETA 允许变化，但避免完全由单秒抖动造成大幅跳变。
4. 连续三秒速度为零、未知总大小、下载暂停或进入校验/解压阶段时隐藏 ETA。
5. 文字必须是“预计剩余下载时间”，不将校验和解压时间假装计入下载 ETA。

## IPC 与组件边界

### Rust 命令与事件

在保持现有 `inspect_frpc_core`、`download_and_extract_core` 行为兼容或有迁移封装的前提下，新增/演进受控能力：

- `scan_local_frpc_cores(directoryPath)`：返回批量识别、跳过项和错误摘要；
- 任务创建与开始下载：接收已验证的 Release/资产/镜像/目标目录/平台信息；
- 任务查询：返回页面恢复状态；
- 继续、取消、清理任务；
- `core-download-progress` 事件：返回任务 ID、阶段、字节、总字节、瞬时速度、ETA、解压条目进度、当前文件名及错误。

Rust 下载管理器负责文件操作、Range/ETag、校验、解压与原子提交；前端不得通过浏览器网络 API 或 `localStorage` 保存归档、哈希、二进制路径以伪造任务状态。

### 前端边界

`CoreManagerPage` 负责读取版本目录和本地安装项、根据当前平台派生卡片状态、打开导入/下载/恢复操作；`CoreCard` 只负责飞书风格的状态和动作呈现；IPC 服务封装命令、事件订阅和浏览器预览环境的安全阻断。现有浏览器预览模式仍不能访问本机文件、下载归档或启动本地 FRPC。

## 错误反馈

- 导入目录无 FRPC：说明未找到 `frpc/frpc.exe`，不增加核心。
- 检测到其他架构：展示已发现架构和当前设备所需架构，保留下载入口。
- 镜像不可用或不支持 Range：说明源和原因，提供切换镜像/重新下载，不自动降级。
- 网络中断：保留可验证缓存并显示“可继续”。
- 哈希、解压或版本验证失败：展示阶段及安全错误说明，拒绝登记为已下载。
- 目标目录冲突或无写入权限：保持用户原有内容，说明需改选目录或处理冲突。

所有路径、错误和日志不得携带 Token、私钥、密码或其他敏感配置。

## 测试与验收

### 前端单元测试

- 版本卡状态按版本 + 当前 OS/架构正确派生；其他架构安装项不误标已下载。
- 同版本本地/在线数据只显示一张 Release 卡。
- 表格“状态”列与卡片状态使用同一状态源；下载中展示正确的阶段和紧凑进度摘要。
- 导入批量结果去重、汇总和错误展示。
- 下载、校验、解压、验真、可继续与失败的进度文案及按钮状态。
- 速度瞬时值、三个样本门槛、EMA ETA、零速隐藏 ETA 的计算。

### Rust 单元与集成测试

- 候选文件筛选、多版本目录、FRPS 排除、重复路径和单项失败不影响其他项。
- Range 正常续传、Range 不支持、ETag 变化、部分文件大小不一致与任务恢复。
- 哈希失败、压缩包路径穿越、解压失败、版本不符、目标目录冲突均不写安装项。
- 成功链路按“下载 → 校验 → 解压 → 验真 → 原子提交”顺序发出进度事件并登记核心。

### 桌面人工验收

1. 导入单版本目录，卡片立即显示无圆点绿色“已下载”。
2. 导入含多个版本目录，全部匹配版本均更新；其他架构版本不会影响当前状态。
3. 选择镜像和新安装目录完成下载，观察下载速度、ETA、校验、解压与验真共用一根进度条。
4. 下载中关闭或取消后重新进入页面，验证继续/清理提示及 Range 不支持的错误说明。
5. 模拟哈希失败、解压失败、验真失败和目录冲突，确认不生成已下载状态且用户原目录不受影响。
