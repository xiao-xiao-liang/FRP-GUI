# FRP-GUI 面向普通用户的体验改造设计

**日期：** 2026-09-01  
**状态：** 待评审  
**目标用户：** 希望使用图形界面完成内网穿透、不希望手写 TOML 的普通用户。

## 1. 背景与目标

现有界面视觉一致且信息完整，但将“方案、FRPC/FRPS、核心、TOML、日志”等技术概念直接暴露在主路径。普通用户必须先理解实现方式，才能完成“远程访问电脑”或“公开家庭 NAS”等目标。概览页还存在重复操作、固定展示数据与诊断入口误开编辑器的问题，降低了操作预期和状态可信度。

本次改造保留现有飞书风格视觉体系、React/Tauri 技术栈、配置兼容性和 TOML 高级能力，将产品重心调整为“连接目标、运行状态和故障恢复”。

完成后，用户应能：

1. 从用途而非 FRP 配置类型开始创建连接；
2. 在一个稳定入口中启动、停止并获取访问地址；
3. 在连接失败时获得可理解的原因、可执行的修复动作和重试路径；
4. 在所有页面看到同一份真实运行状态。

## 2. 信息架构

默认页面改为 **我的连接**，左侧主导航调整为：

| 导航 | 用户任务 | 页面职责 |
| --- | --- | --- |
| 我的连接 | 创建、启停、访问服务 | 展示全部用户目标及其状态；提供创建连接和打开详情。 |
| 运行状态 | 观察当前运行情况 | 仅聚合正在运行的连接、真实流量、最近活动和异常。 |
| 排障中心 | 解决连接失败 | 关联某个连接的检测结果、错误日志、修复建议和重试操作。 |
| 设置与核心 | 管理低频高级配置 | FRP 核心、导入导出、二维码同步和高级 TOML 能力。 |

“FRPC / FRPS”“核心”“TOML”不再作为普通用户的首层导航词。高级用户仍可在连接详情和设置中访问它们；既有配置、导入、编辑和运行能力保持兼容。

## 3. 核心用户流程

### 3.1 创建连接

1. 用户点击“创建连接”。
2. 选择用途：远程桌面、SSH、公开网站、家庭 NAS、游戏联机或自定义。
3. 系统仅显示该用途所需的字段，例如服务器地址、端口、本地服务地址和认证信息；高级设置折叠。
4. 用户点击“检查并保存”。系统校验必填项、当前核心、服务器连通性和端口可用性。
5. 成功时显示生成的访问入口，并提供“立即启动”；失败时在对应字段和结果区说明原因及修复动作。

### 3.2 日常启停与访问

“我的连接”中的每个条目只突出一个与状态相符的主操作：未启动时为“启动连接”，运行中时为“停止连接”，失败时为“立即排查”。条目同时展示名称、用途、用户可用的访问地址和文字化状态。

日志、编辑、扫码、克隆和删除等低频动作移入连接详情或“更多”菜单。连接启动成功后，系统按场景提供可复制的 SSH 命令、网址或远程桌面地址，避免用户自行拼接。

### 3.3 排障与恢复

当启动、运行监测或手动测试失败时，连接状态改为“需要处理”，并说明用户语言的原因，例如“服务器端口未响应”。点击“立即排查”后，排障中心自动带入：

- 该连接标识；
- 最近一次诊断结果；
- 关联的错误日志；
- 推荐修复动作，如检查服务器地址、重新选择核心、修改端口或重试检测。

修复并重试成功后，状态自动回写到“我的连接”和“运行状态”。日志作为诊断证据，而不是故障用户必须先学会阅读的入口。

## 4. 状态模型与数据流

连接状态统一为：`未启动`、`启动中`、`正常运行`、`需要处理`。状态对象至少包含运行态、原因、最后检测时间、关联核心、PID（如有）和最近错误摘要。

```text
FRP 进程 / 本地核心 / 网络诊断 / 日志流
                 ↓
          连接状态模型（唯一来源）
                 ↓
我的连接 / 运行状态 / 排障中心 / 连接详情
```

所有视图从同一状态模型派生数据。无真实数据时显示“暂无数据”或“未配置”，不得显示固定版本、固定速率或模拟运行状态。核心未配置时，启动前给出明确阻断和“配置核心”入口。

## 5. 页面与组件改造

### P0：操作可信与故障闭环

1. 接入真实网络诊断弹窗；“网络连通检测”不得打开新建方案弹窗。
2. 统一启动、停止、检测、保存的加载、成功、失败和可恢复提示。
3. 概览和导航使用真实核心版本、真实连接状态和真实统计；无数据时不做模拟展示。
4. 从异常连接直接进入该连接的日志和诊断上下文。

### P1：高频体验重排

1. 将方案管理升级为“我的连接”，默认进入该页。
2. 合并重复筛选：保留搜索和一组筛选器；状态 Tab 只承载高频状态。
3. 连接卡仅保留主操作和“打开详情”，将低频动作折叠。
4. 创建/编辑界面采用场景引导、必要字段优先和高级设置折叠；TOML 保留为高级模式。
5. 概览页移除重复操作，改为待处理事项、运行摘要和访问入口。

### P2：效率、保护与可访问性

1. 提供可筛选的运行与排障历史。
2. 未保存修改离开提醒；批量操作显示影响数量与范围；删除后提供短暂撤销机会。
3. 补齐键盘焦点、图标文字标签、表单错误定位和窄窗口布局。
4. 二维码、备份和核心下载保留在设置与核心，后续根据使用数据决定是否继续强化入口。

## 6. 错误处理与边界

- 诊断失败必须展示原因和“重试”或“编辑配置”入口；不能只显示笼统错误码。
- 停止运行中的连接需确认会中断已有访问；批量停止需显示受影响连接数量。
- 当核心缺失、路径无效或版本不兼容时，禁止误报“就绪”。
- 从 TOML 进入高级编辑时保留原有双向同步与兼容行为；表单无法表达的内容不可静默丢失。
- 日志或流量尚不可用时，视图显示不可用原因而非伪造指标。

## 7. 验收与验证

### 功能验收

1. 点击“网络连通检测”打开真实诊断流程。
2. 启动失败后，用户能看到具体原因并从当前连接进入诊断或编辑。
3. 未配置核心时，界面不显示可用版本或“就绪”。
4. 已有 TOML、导入、日志、备份和核心管理功能保持可用。

### 任务走查

1. 不懂 TOML 的用户可以完成一次 NAS 或远程桌面连接创建、校验、保存和启动。
2. 用户可以从“需要处理”的连接完成诊断、修复并重新启动。
3. 用户可以停止一个运行中的连接，并明确知晓连接中断的影响。

### 技术验证

1. 执行项目既有 TypeScript 构建与打包检查。
2. 针对状态映射、诊断入口、启动失败、筛选和关键操作补充或更新测试。
3. 人工走查桌面窄窗口与正常窗口，检查键盘焦点、图标标签、错误提示和未保存提醒。

## 8. 非目标

- 本轮不替换飞书视觉体系，不进行无关的组件重写。
- 本轮不移除高级 TOML 或 FRPC/FRPS 能力。
- 本轮不改变已有配置格式、核心下载来源或外部接口，除非实现真实状态所必需。
- 本轮不承诺移动端完整重构；先保证桌面和窄窗口的可理解性。
