# FRP-GUI P1-C「FRP 全生命周期控制台」设计规格

## 目标

让普通用户在 FRP-GUI 内完成远程 Ubuntu/Debian 云服务器上的 FRPS 部署、配置、运行与开机自启，并将已部署服务器作为 FRPC 场景化向导可复用的节点，尽量不接触 Shell、Bash 或 PowerShell。

## 范围

- 远程 Linux FRPS：仅 Ubuntu/Debian；支持 `root` 和具备 `sudo` 权限的普通用户。
- SSH 登录：密码或私钥；用户可选“记住凭证”。
- 一键部署：系统/权限预检、下载 FRPS、生成 `frps.toml`、创建并启用 `systemd` 服务、启动与状态回传。
- 节点复用：FRPC 新建向导从已部署节点选择服务器地址、端口与 Token，不要求重复输入。
- 运行管理：节点状态、版本、配置摘要、服务日志、启动、停止、重启、重新部署。

不包含：CentOS/RHEL、云厂商账号购买/安全组自动配置、多服务器集群、远程桌面 GUI 运维、自动升级/回滚策略。

## 产品路径

```text
添加远程 Linux 节点
  -> SSH 连通性、发行版、架构、root/sudo、systemd 预检
  -> 选择稳定版与安装目录
  -> 部署计划确认
  -> 下载/配置/创建 systemd 服务/启动
  -> 节点就绪并设为默认
  -> 新建 FRPC 场景连接时选择该节点
  -> 本地 FRPC 启动时沿用既有核心阻断与引导
```

每一步失败都停在当前步骤，展示脱敏后的原因、可重试操作和返回修改入口；不得把未完成部署标为就绪。

## 领域模型与边界

### 服务器节点

新增 `FrpServerNode`，保存非敏感信息：`id`、名称、主机、SSH 端口、用户名、认证方式、FRPS bind 端口、管理端口、安装目录、FRPS 版本、状态、默认标记、最近检测时间与最近错误。

认证值不属于节点配置：密码、私钥内容、私钥口令和 FRP Token 都写入操作系统安全凭据库；节点模型只持有不可逆的引用标识。删除节点时必须提供同时删除安全凭据引用的选项。

### 配置责任

- FRPS：图形表单生成 `frps.toml`；高级模式允许查看/编辑，保存前校验并明确提示会重启服务。
- FRPC：场景向导选择节点后只显示场景字段；地址、端口和 Token 在后台注入 `FrpcConfig` 与 TOML。普通模式不回显 Token。
- 现有 `FrpCore` 继续只描述本机可执行核心；远程 FRPS 版本和服务状态属于服务器节点，二者不混用。

## 安全与执行原则

- SSH、下载、文件写入与服务控制均在 Tauri Rust 后端执行；前端不得执行或拼接可直接运行的 Shell 命令。
- 后端根据认证方式从安全凭据库读取凭据，命令参数结构化传递，避免字符串拼接注入。
- 首次部署前展示步骤摘要：系统预检、下载版本、安装目录、配置路径、服务名和将使用的端口。
- 执行日志必须脱敏密码、Token、私钥内容和私钥口令；页面、Toast 与本地存储不得出现这些值。
- `sudo` 仅在预检确认可用时执行；不可用时明确告知用户改用 root 或授予 sudo 权限。

## 部署与运行状态

节点状态为：`draft`、`checking`、`ready_to_deploy`、`deploying`、`running`、`stopped`、`error`。只有成功完成健康检查后才能进入 `running`；中断或失败进入 `error` 并保存脱敏错误。

部署成功标准：FRPS 二进制存在、`frps.toml` 可解析、`frps.service` 已创建并 enabled、服务处于 active，且 bind 端口检测通过。

## 验收标准

1. 用户可用密码或私钥添加 Ubuntu/Debian 节点，并可选记住凭证。
2. 无 root 但可 sudo 的账号可完成部署；无 sudo 权限时被安全阻断并得到可操作提示。
3. 成功部署后 FRPS 服务自动启动且设为开机自启，节点显示版本和运行状态。
4. 部署失败、SSH 失败或端口检查失败不会产生“已就绪”假状态。
5. 新建 FRPC 连接可选择默认节点，普通页面和日志不显示 Token。
6. 已有 P0/P1-A/P1-B 的启动阻断、诊断隔离、连接筛选与场景创建回归通过。

## 实施拆分

1. P1-C1：服务器节点数据模型、安全凭据适配与节点管理页面。
2. P1-C2：SSH 预检与主机信任，不执行任何远程写入。
3. P1-C3：FRPS 配置、经 checksum 校验的下载与部署、systemd 服务运行管理与脱敏日志；支持 root、免密 sudo 和需 sudo 密码的普通用户。
4. P1-C4：FRPC 向导复用默认节点、端到端回归与文档。

每个子阶段必须独立测试与验收；P1-C1 不执行远程命令，P1-C2 仅执行只读预检，P1-C3 才引入真实部署能力。
