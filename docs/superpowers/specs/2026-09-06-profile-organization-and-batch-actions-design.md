# Profile 组织与批量编排设计

## 背景与目标

当前 Profile 列表已具备状态、类型和关键词筛选，以及“全部启动”“全部停止”能力，但随着连接数量增加，用户无法按用途整理方案，也无法针对一个筛选结果执行安全、可预期的批量操作。

本次功能为 Profile 增加扁平分组、标签、置顶、排序、组合筛选和批量编排能力。所有新增组织数据均为非敏感元数据；现有 TOML、Token 和其他凭据继续由系统凭据库管理，不能写回 `localStorage`。

## 范围

### 用户能力

- 创建、重命名和删除扁平分组。
- 为 Profile 设置一个分组、最多十个标签和置顶状态。
- 按分组、标签、运行状态、协议类型和关键词组合筛选。
- 在“置顶且最近更新”“最近更新”“名称”三种排序中选择默认排序。
- 在筛选结果中跨页选择 Profile，并批量启动、停止、移动分组或删除。
- 在卡片和表格视图中显示置顶、分组与标签信息。

### 不在范围内

- 嵌套分组、拖拽排序、跨设备同步、分享和权限控制。
- 节点健康巡检、端口冲突检测、备份恢复、核心升级管理。
- 改变 FRPC 启停协议、Profile 凭据存储方式或二维码安全边界。

## 数据模型与持久化

### Profile 扩展字段

在 `Profile` 中增加以下可选字段，并保持旧数据兼容：

```ts
groupId?: string
tags?: string[]
isPinned?: boolean
```

读取旧 Profile 时，缺失字段分别按“未分组、空标签、未置顶”处理。写回前应规范化标签，不能把 `rawToml` 或任意凭据带入组织数据。

### 分组模型

```ts
interface ProfileGroup {
  id: string
  name: string
  createdAt: number
  updatedAt: number
}
```

分组独立保存到 `localStorage` 键 `frp_gui_profile_groups`。Profile 仍保存到既有 `frp_gui_profiles`；该记录继续经过 `sanitizeProfileForStorage`，凭据仍仅通过现有系统凭据库与 IPC 存取。

删除分组时不删除 Profile，只将所有引用该分组的 `groupId` 清空。分组名称去除首尾空白后必须为 1–30 个字符，并在当前分组集合中按不区分大小写的方式唯一。

标签去除首尾空白后必须为 1–24 个字符；单个 Profile 最多十个标签，按不区分大小写去重，并保留用户首次输入的显示形式。

### 设置迁移

在 `AppSettings` 中增加：

```ts
profileSort: 'pinned_updated' | 'updated_desc' | 'name_asc'
```

默认值为 `pinned_updated`。设置读取必须采用字段级兼容：旧版本设置缺少该字段时补默认值；单个新字段非法时仅回退该字段，不能使其余有效设置整体丢失。

## 展示、筛选与排序

筛选条件采用“全部满足”语义：分组、标签、状态、类型和关键词同时生效。关键词继续匹配名称与描述；空筛选表示全部 Profile。

排序在筛选之后执行，并使用稳定、确定的比较规则：

1. `pinned_updated`：置顶优先，再按 `updatedAt` 降序；
2. `updated_desc`：按 `updatedAt` 降序；
3. `name_asc`：按名称的 ASCII/Unicode 代码点顺序升序；
4. 主比较相同一律以 `id` 升序作为最终兜底。

改变任一筛选条件、排序或数据集合时，分页返回第一页。卡片和表格显示分组名、最多两个标签和“另有 N 个”提示；无分组或无标签时不显示空占位。置顶操作可在单项菜单中完成。

## 选择与批量操作

选择状态由 `ProfileList` 持有，为非持久化的 `Set<string>`。选择框作用于当前筛选结果，而不是当前页；改变筛选条件、Profile 删除或外部数据更新后，应自动清除已不可见或不存在的选择项。

批量工具条仅在选择至少一项时出现，并展示已选择数量。批量操作通过回调上交 `App`，由 `App` 复用既有单项生命周期操作，避免复制 FRPC 启停逻辑。

| 操作 | 允许目标 | 执行语义 |
| --- | --- | --- |
| 批量启动 | `stopped`、`error` | 按当前排序顺序串行调用既有启动逻辑；其他状态跳过并显示数量。 |
| 批量停止 | `running` | 二次确认后按当前排序顺序串行调用既有停止逻辑；其他状态跳过并显示数量。 |
| 移动分组 | 任意状态 | 只更新 `groupId`，可选择“未分组”，不触碰凭据与运行状态。 |
| 批量删除 | `stopped`、`error` | 若任一已选项处于 `starting`、`running` 或 `stopping`，禁用删除并说明原因；确认后逐项复用既有删除与凭据清理逻辑。 |

执行过程中禁用批量工具条，避免重复请求。每次操作结束后保留仍存在且仍可见的选择；删除成功的项目从选择中移除。浏览器预览环境继续沿用现有 Tauri 操作拦截规则，不能以模拟成功替代实际错误反馈。

克隆 Profile 时复制分组和标签，且新 Profile 强制 `isPinned: false`，避免克隆结果挤占置顶区。

## 模块职责

- `src/types/frp.ts`：声明组织数据类型与 Profile 扩展字段。
- `src/services/profile-organization.ts`：纯函数，负责输入规范化、分组校验、筛选、排序、选择目标计算和本地存储读写。
- `src/services/app-settings.ts`：增加 `profileSort` 的字段级迁移和校验。
- `src/features/profiles/ProfileGroupManagerDialog.tsx`：分组创建、重命名、删除与提示。
- `src/features/profiles/ProfileList.tsx`：筛选控件、选择状态、批量工具条、卡片/表格传参。
- `src/features/profiles/ProfileCard.tsx`：单项置顶、选择和组织元数据展示。
- `src/App.tsx`：持有分组数据与业务操作回调；复用既有启动、停止、删除、凭据清理和持久化流程。
- `src/features/settings/SettingsPage.tsx`：提供默认 Profile 排序设置。

## 失败处理与安全边界

- 本地存储损坏或无法解析时，以空分组和默认排序启动，并保留已有 Profile 处理方式；界面给出可理解的错误提示。
- 分组删除、批量停止和批量删除必须确认。批量删除前必须先检查所有选择项状态。
- 新增本地存储内容仅限组 ID、名称、时间戳、标签、置顶和排序偏好；禁止写入 TOML、Token、服务器密码、私钥或凭据引用以外的秘密。
- 不新增网络请求、后端命令或跨进程 API。
